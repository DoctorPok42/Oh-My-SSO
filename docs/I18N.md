# Languages (i18n)

Oh-My-SSO shows its sign-in pages, account console, e-mails and admin console in the
reader's language. Built-in: English and French.

## Principle

English is the language of the code. Every text is written in English where it is used,
next to a key that names it:

```go
loc.T("account.flash.profile_saved", "Your name was saved.")        // Go
i18n.M("admin.error.last_admin", "...")                             // Go, a text for later
```
```html
{{t "login.title.sign_in" "Sign in"}}                               <!-- templates -->
```
```ts
t("users.title", "Users & Roles")                                   // admin console
tn("sessions.count", n, "{count} session", "{count} sessions")
```

English needs no file. Each other language is one flat JSON file, key → text. A missing
key falls back to English. Placeholders are `{name}`. Plurals use `key.one` / `key.other`.

| Part | Built in | Added without a rebuild | Check |
|---|---|---|---|
| IdP (pages, account console, e-mails, Admin API errors) | `internal/i18n/locales/<lang>.json` | `LOCALES_DIR` (idp and idp-admin) | `go test ./internal/i18n/` (`TestCatalog`) |
| Admin console (Next.js) | `admin/src/i18n/translations/<lang>.json` | `ADMIN_LOCALES_DIR` | `npm run i18n:check` (also in CI) |

The checks fail on a missing key, an unused key, or placeholders that differ from the English.

## Which language is shown

| Where | Order (first available wins) |
|---|---|
| IdP pages and account console | 1. the user's choice (account console, profile `locale`) · 2. `ui_locales` of the OIDC request · 3. the `omsso_locale` cookie (this browser) · 4. the realm's default (Settings › `default_locale`) · 5. English |
| E-mails | 1. the user's choice · 2. the realm's default · 3. English (no browser to ask) |
| Admin console | 1. the admin's choice (`GET /me/language`, else the `locale` claim of the ID token) · 2. the `omsso_locale` cookie · 3. the default of the admin's realm (`GET /me/language`) · 4. English |
| Admin API error messages | the console's language, sent as `Accept-Language` |

- **The user's choice.** It is set in the account console (`/account/language`), stored in
  the profile as `locale`, and also issued as the OIDC `locale` claim.
- **The cookie.** `omsso_locale` belongs to the browser and is shared by the IdP pages and
  the admin console. After sign-in it takes the account's language.
- **Admin console timing.** The console keeps `GET /me/language` for 30 seconds (read cache,
  emptied by any change made in the console). A change in Settings shows on the next page, one
  in the account console within 30 seconds; there is no need to sign in again.

## What stays in English

- Everything written to a terminal: logs and `idp-admin` CLI output (`bootstrap`,
  `recover`).
- The stable error `code` of the Admin API (`invalid_request`, `name_taken`…). Only the
  `message` is translated.

## Add or change a language

### Without changing the code

Two directories of `<tag>.json` files, one per part, because the two catalogues have
different keys:

| Variable | Read by | Set in |
|---|---|---|
| `LOCALES_DIR` | idp and idp-admin (same directory for both) | `.env` |
| `ADMIN_LOCALES_DIR` | the admin console | `admin/.env.local`, or the container's environment |

```
locales/de.json          {"language.name": "Deutsch", "login.title.sign_in": "Anmelden", ...}
admin-locales/de.json    {"language.name": "Deutsch", "users.title": "Benutzer & Rollen", ...}
```

- **When they are read.** At start-up only: restart to take a change.
- **Adding or changing.** A new tag adds a language. A built-in tag (`fr.json`, or
  `en.json` for English) changes only the keys it contains; the other texts stay.
- **Missing or empty texts.** A missing key, or an empty text, shows the built-in or
  English text.
- **File names.** A language tag, in any case: `de.json`, `pt-br.json`, `pt_BR.json`.
- **Errors.**
  - The admin console stops at start-up, with the file and the reason, when a file is
    wrong (not JSON, not an object of texts) or when the directory cannot be read.
  - The IdP stops on a wrong file, but ignores a missing directory: check the path.
- **Docker.** Mount the directories read-only. See the commented lines of
  `compose.example.yml`.

Check the files before deploying, from a checkout of the same version:

```
cd admin && npm run i18n:check -- --dir /path/to/admin-locales
```

It reports missing keys, keys the code no longer uses, and placeholders that differ.
There is no such command for `LOCALES_DIR`.

### In the code (a built-in language)

1. **IdP.** Add `internal/i18n/locales/<tag>.json`, including `"language.name"` (the
   language's own name, e.g. `"Deutsch"`). The file is compiled into the binary.
2. **Admin console.** Add `admin/src/i18n/translations/<tag>.json`, then one line in
   `BUILT_IN` (`admin/src/i18n/catalog.ts`).
3. **Check.** Run `go test ./internal/i18n/` and `cd admin && npm run i18n:check`.

### Where the language appears

A language of the IdP appears in the account console's language list and in each
realm's Settings › default language. Give it to the admin console too, otherwise the
console shows that language in English.
